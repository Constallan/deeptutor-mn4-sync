# MarginNote 4 卡死修复计划

## 目标

保留同步对象字段和顺序，消除插件可控制的长时间连续主线程扫描；停用或场景断开后不得继续读取数据库或发送新请求。已发送的异步请求无法通过现有接口撤回，可能仍在服务端完成；旧回调必须禁止写回同步状态或安排后续工作。

## 阶段 1：建立回归信号

1. 新增 Node 模拟桥接测试，使用带计数 getter 的学习集、笔记和文档对象加载真实 `main.js`。
2. 固定 20,434 条笔记加一个文档场景，断言关系属性每学习集只读取一次，并记录模拟 getter 成本下的分片耗时和让出次数；真实耗时另在 Mac 测量。
3. 覆盖停用、场景断开、同步防重入、请求失败后恢复等生命周期。
4. 保留现有语法检查和敏感信息扫描。

## 阶段 2：消除桥接访问放大

1. 将 `topic.notes`、`topic.documents`、`note.linkedNotes` 缓存为局部变量。
2. 在对象转换入口一次性读取所需原生字段，后续只访问普通 JavaScript 值。
3. 同一学习集内，文档字段缓存后复用于标题映射及文档上传；不跨同步周期缓存，避免遗漏修改。保留跨学习集的原有对象输出语义。
4. 先运行 getter 计数测试，确认修复前失败、修复后通过。

## 阶段 3：改为可让出的流式同步

1. 将同步拆成小型收集分片；每片预算 8 ms 或最多 25 步，之后通过 0.01 秒一次性定时器让出事件循环。数据库入口、文档标题、笔记、链接列表均纳入状态机；JSON 序列化安排在单独的定时器回调中。
2. 收集到一个上传批次后立即发送并释放，禁止一次性保存全部对象及全部批次闭包。
3. 以同步代际编号实现取消；停用、重置或场景断开后，旧代际不得继续收集或排队。
4. 保存实际定时器引用并显式失效，避免残留回调。

## 阶段 4：降低周期工作量

1. 60 秒周期只执行轻量心跳。
2. 优先调查 MarginNote 的变更通知或按修改时间查询接口，实现真正增量同步。
3. 未确认可靠增量接口时采用分片全量扫描：启用/重连首次扫描，之后完成或失败后等待 15 分钟；“立即同步”继续提供显式全量路径。60 秒心跳独立运行，等待心跳响应后再计时。

接口调查（2026-09-10）：[MarginNote 官方插件开发指南](https://docs-addon.marginnote.cn/guide/) 列出 `allNotebooks`、按 ID 取对象及笔记 `modifiedDate` 属性；未找到按修改时间筛选的数据库查询或有完整性保证的变更流。仅在全库读取后比较修改时间无法解决本次扫描问题。该指南为预览版，未确认的 MN4 私有接口不作为本次修复依赖；不能据此断言所有版本均无增量接口。

## 验收标准

- 自动化检查全部通过，模拟桥接场景中对象数量、字段和顺序正确；真实服务端结果另行验收。
- 20,434 对象场景中，单个 JavaScript 工作分片目标不超过 50 ms。定时器不能打断单个原生 getter 或序列化，超限必须结合采样继续分析，不能把模拟时钟结果当作硬保证。
- 停用或场景断开后，getter 计数和请求计数不再增长。
- 在同一 Mac 数据库上连续运行至少三个同步周期，无彩虹圈、无持续内存增长。
- 修复后重新采样：主线程不再连续停留于 `NSTimer → getter → Core Data fetch`，并与未加载插件基线对照记录。

## 实施顺序

按“测试 → 缓存 getter → 分片收集 → 流式上传 → 生命周期取消 → Mac 复测”拆成小提交。每一步独立保持语法正确和同步结果不变，便于回退与定位回归。

## 实施记录

- 已实现 getter 缓存、含链接遍历的分片收集、500 条流式串行上传、代际取消、显式定时器失效与独立心跳。
- 修复请求失败未记录 `lastError` 的原有分支；请求批次失败后继续其余批次，最终保留失败状态，下次全量扫描重试。无法转换的必要字段或数据库读取异常中止本次扫描并记录错误，避免原有静默跳过导致的假成功。
- 已增加 `tests/sync-check.js`，修复前失败，修复后通过；包括 20,434 条笔记和生命周期边界。
- 内存只保留当前批次、当前学习集关系和文档映射，以及学习集列表；原生 API 返回的完整关系集合仍可能较大。没有一次性保存整库导出对象或所有批次闭包。
- 已在原问题 MarginNote 环境安装并实测 1.1.3，未再出现此前的长时间卡顿。尚未提供修复后采样、三周期内存趋势或真实 DeepTutor 逐字段核对结果，不据此扩大结论。
- 补齐 P2 回归：三个上传批次中仅首批失败，断言后两批仍成功上传、最终保留错误且下次全量重试恢复；三个学习集（含空学习集、共享文档）跨批次输出逐项比对顺序、出现次数、类型和文档标题。
- 构建 `dist/deeptutor-mn4-sync-1.1.3.mnaddon`，版本号更新为 1.1.3；包内文件与当前源码一致，原问题场景实测无卡顿。

## Mac 验收记录与后续复测

1. 已在原问题数据库安装本分支构建的 1.1.3 插件并确认不再卡顿；既有 1.1.2 发布包不包含本次修复。后续复测应补记 MarginNote、macOS、DeepTutor 完整版本及对象规模。
2. 启用后持续滚动、切换笔记、编辑内容；观察首次同步及其后至少两个自动扫描周期（完成后各等待 15 分钟）。检查每分钟心跳期间没有新整库扫描。
3. 对照服务端对象数量及笔记/卡片/脑图/文档字段；修改内容后使用“立即同步”确认更新。
4. 分别在收集中和上传中停用、断开场景、重置；确认不再发起新批次。允许此前已经发出的请求完成。重连或重新配置后确认恢复且无重复循环。
5. 在扫描期间和空闲期间分别采样并记录内存，和本机留存的原始基线比较；保存每片耗时或观察到的长原生调用。原始采样不得提交到版本库。至少三周期无彩虹圈、无持续内存增长后，再标记原生验收完成。
